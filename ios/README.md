# iOS app

raylib DOOM for iPhone, as an Xcode project generated by CMake. raylib runs
on its SDL2 platform (UIKit and OpenGL ES 2); CMake downloads SDL2 2.30 and
raylib 5.5 and builds both as static libraries. The game has the same touch
buttons as the Android app, and also takes a Bluetooth gamepad. It runs in
landscape only.

You need a Mac with Xcode 15 or newer (with the iOS SDK) and CMake 3.24+.

## An IWAD

No game data is included. Bundle the shareware `DOOM1.WAD` or Freedoom's
`freedoom1.wad` / `freedoom2.wad`, or leave it out and copy one into the app's
Documents folder later (the app shows up in the Files app, under "On My
iPhone"). The app looks in `$DOOMWADDIR`, then Documents, then its own bundle.
Saved games and `.doomrc` are kept in the app's sandbox as well (saved games
in Documents).

## Simulator

```sh
cmake -S . -B build-ios-sim -G Xcode \
  -DCMAKE_SYSTEM_NAME=iOS -DCMAKE_OSX_SYSROOT=iphonesimulator \
  -DCMAKE_OSX_ARCHITECTURES=arm64 -DRAYLIB_DOOM_IOS=ON \
  -DRAYLIB_DOOM_IOS_IWAD=/path/to/freedoom1.wad
xcodebuild -project build-ios-sim/raylib_doom.xcodeproj -scheme raylibdoom \
  -configuration RelWithDebInfo -sdk iphonesimulator \
  -derivedDataPath build-ios-sim/DerivedData CODE_SIGNING_ALLOWED=NO build

xcrun simctl boot "iPhone 17 Pro"
xcrun simctl install booted build-ios-sim/RelWithDebInfo-iphonesimulator/raylibDOOM.app
xcrun simctl launch --console-pty booted com.raydelto.raylibdoom
```

Use `-DCMAKE_OSX_ARCHITECTURES=x86_64` on an Intel Mac. Build output is large;
point `-derivedDataPath` and the build directory at an external disk if the
internal one is short of space (`xcrun simctl --set <dir>` keeps the simulator
devices there too).

## iPhone

```sh
cmake -S . -B build-ios -G Xcode \
  -DCMAKE_SYSTEM_NAME=iOS -DCMAKE_OSX_SYSROOT=iphoneos \
  -DCMAKE_OSX_ARCHITECTURES=arm64 -DRAYLIB_DOOM_IOS=ON \
  -DRAYLIB_DOOM_IOS_IWAD=/path/to/freedoom1.wad \
  -DRAYLIB_DOOM_IOS_BUNDLE_ID=com.example.raylibdoom \
  -DRAYLIB_DOOM_IOS_TEAM=<your team id>
```

Choose a bundle id of your own (a free "Personal Team" needs a unique one) and
your development team's ID (Xcode > Settings > Accounts). Then:

1. Connect the iPhone and tap Trust on it.
2. Turn on Developer Mode (Settings > Privacy & Security > Developer Mode;
   the phone restarts).
3. Build and sign:
   ```sh
   xcodebuild -project build-ios/raylib_doom.xcodeproj -scheme raylibdoom \
     -configuration RelWithDebInfo -destination 'generic/platform=iOS' \
     -derivedDataPath build-ios/DerivedData -allowProvisioningUpdates build
   ```
   (`CODE_SIGNING_ALLOWED=NO` builds without signing, which checks that the
   code compiles but gives an app the phone will not run.)
4. Install and start it:
   ```sh
   xcrun devicectl list devices
   xcrun devicectl device install app --device <device id> \
     build-ios/RelWithDebInfo-iphoneos/raylibDOOM.app
   xcrun devicectl device process launch --device <device id> com.example.raylibdoom
   ```
5. The first launch says the developer is untrusted: Settings > General > VPN
   & Device Management > your Apple ID > Trust. Apps from a free team stop
   working after seven days; install again to renew.

## How it differs from the other builds

* `RAYLIB_DOOM_IOS` selects `i_ios.m`, the iOS branches of `i_main.c`,
  `i_raylib.c` and `i_system.c`, and makes `main` into SDL's `SDL_main`.
  `DOOM_IOS` (from `i_ios.h`) is defined on iOS only, so the macOS build, and
  every other one, is unchanged.
* The picture is drawn into UIKit's own framebuffer and renderbuffer, which
  SDL presents; raylib's default framebuffer 0 shows nothing on iOS.
* Retina: the window is in points, so iOS scales the 1x drawable up. raylib's
  SDL platform has no DPI scale.
* When the app is about to go to the background, nothing is drawn and the game
  waits (iOS kills an app that draws with OpenGL ES in the background). The
  game's clock stops meanwhile.
* The touch buttons keep out of the safe area (Dynamic Island, rounded
  corners, home indicator), and read SDL's finger list, because raylib's SDL
  platform reports the first finger as the mouse.
* Sound is an ambient `AVAudioSession`: it follows the silent switch.
